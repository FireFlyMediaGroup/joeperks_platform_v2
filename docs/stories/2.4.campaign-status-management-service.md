## User Story

As an **organization admin or campaign manager**,
I want **to change campaign status and manage campaign lifecycle states**,
So that **I can control when campaigns are active and respond to changing circumstances**.

3. Campaign status history is tracked with timestamps and reasons

## Campaign Lifecycle States

**Supported States:**
1. **Draft**: Campaign being created and configured
2. **Pending**: Awaiting approval or roaster partnership
3. **Active**: Live campaign accepting orders
4. **Paused**: Temporarily suspended campaign
5. **Completed**: Successfully finished campaign
6. **Cancelled**: Terminated campaign before completion

**Valid Transitions:**
- Draft → Pending, Active, Cancelled
- Pending → Active, Cancelled
- Active → Paused, Completed, Cancelled
- Paused → Active, Completed, Cancelled
- Completed/Cancelled → No transitions (terminal states)

## Dev Notes

### Previous Story Integration
**From Story 2.1**: Organization Management Service provides organization context and permissions.
**From Story 4.1**: Campaign Management Service provides core campaign CRUD operations.

### Data Model Extensions
**Campaign Entity Updates** [Source: architecture/database-schema.md#campaigns]:
- Add status field: status ENUM (draft, pending, active, paused, completed, cancelled)
- History tracking: status_changed_at, status_changed_by, status_change_reason
- Audit fields: previous_status, status_change_count

### Status Change Business Rules
**Validation Requirements**:
- Only campaign admin/manager can change status
- Status transitions must follow valid state machine
- Completed campaigns cannot be reactivated without admin approval
- Cancelled campaigns require reason for audit purposes

### Notification Integration
**Status Change Notifications**:
- Campaign team notifications on status changes
- Organization admin alerts for important transitions
- Member notifications when campaigns go active/pause
- Automatic reminders for draft campaigns

## Risk Assessment

**Primary Risk:** Invalid status transitions causing data inconsistency
**Mitigation:** Strict state machine validation and atomic database transactions
**Rollback:** Feature flag to disable status management if issues arise
