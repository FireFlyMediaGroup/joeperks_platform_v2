### Data Models Integration
**Campaign Entity Operations** [Source: architecture/database-schema.md#campaigns]:
```sql
-- Campaign management with organization isolation
CREATE TABLE campaigns (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    organization_id UUID REFERENCES organizations(id) ON DELETE CASCADE,
    name VARCHAR(255) NOT NULL,
    slug VARCHAR(100) NOT NULL,
    description TEXT,
    fundraising_goal DECIMAL(10,2) NOT NULL,
    current_raised DECIMAL(10,2) DEFAULT 0,
    start_date TIMESTAMP,
    end_date TIMESTAMP,
    status VARCHAR(50) DEFAULT 'draft',
    campaign_settings JSONB DEFAULT '{}',
    branding_overrides JSONB DEFAULT '{}',
    created_by UUID REFERENCES users(id),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(organization_id, slug)
);
```

**Campaign Data Model** [Source: architecture/data-models.md#campaign]:
- **Purpose**: Individual fundraising initiatives run by organizations
- **Key Attributes**: name, slug, fundraising_goal, current_raised, start_date, end_date, status
- **Relationships**: Belongs to organization, has many orders, has many campaign products

**Campaign Status States**:
- `draft` - Campaign being configured, not yet public
- `scheduled` - Campaign configured, waiting for start date
- `active` - Campaign live and accepting orders
- `paused` - Campaign temporarily suspended
- `completed` - Campaign ended successfully
- `cancelled` - Campaign terminated before completion
- `archived` - Campaign moved to historical records

### Component Specifications
**Campaign Management Service** [Source: architecture/components.md#campaign-management-service]:
- **Primary Responsibility**: Campaign lifecycle, goal tracking, and performance analytics
- **Key Interfaces**: Campaign CRUD, goal management, analytics reporting, product selection
- **Dependencies**: Organization service for branding, product service for inventory, order service for tracking
- **Technology**: Custom Medusa.js services with PostgreSQL storage and Redis caching

- `GET /campaigns/{id}/analytics` - Campaign performance metrics

### Technical Constraints
**Multi-Tenant Isolation** [Source: architecture/security-considerations.md#data-protection]:
- Campaign data must be isolated by organization_id
- Organization context must be validated from JWT tokens
- Campaign access must respect organization member roles
- Cross-organization campaign access must be prevented

**Campaign Lifecycle Rules**:
- Draft campaigns can be freely modified
- Active campaigns have restricted modification rules
- Completed campaigns become read-only with analytics access
- Cancelled campaigns retain data for audit purposes
