# Story 1.2: Database Schema & Migrations Implementation

## Status
Draft

## Story
**As a** platform developer,
**I want** to implement the core database schema with Stytch integration and create migration scripts,
**so that** the authentication service and other platform components have the required data structures for multi-tenant operations.

## Acceptance Criteria
1. Core user management tables are created with Stytch integration fields
2. Organization tables support multi-tenant architecture with Stytch organization IDs
3. Organization members table enables RBAC with Stytch membership sync
4. Roaster tables include Stytch organization integration
5. Customer session management tables support guest checkout workflows
6. All required indexes are created for performance optimization
7. Database migrations are reversible and follow project SQL migration conventions (up/down)
8. Seed data is available for development and testing environments

### Data Models
**Users Table Schema** [Source: architecture/database-schema.md#users]:
```sql
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    stytch_user_id VARCHAR(255) UNIQUE NOT NULL,
    email VARCHAR(255) UNIQUE NOT NULL,
    given_name VARCHAR(255),
    family_name VARCHAR(255),
    user_type VARCHAR(50) NOT NULL CHECK (user_type IN ('platform_admin', 'roaster', 'organization', 'customer')),
    status VARCHAR(50) DEFAULT 'active',
    last_login TIMESTAMP,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

**Organizations Table Schema** [Source: architecture/database-schema.md#organizations]:
```sql
CREATE TABLE organizations (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    stytch_org_id VARCHAR(255) UNIQUE NOT NULL,
    name VARCHAR(255) NOT NULL,
    slug VARCHAR(100) UNIQUE NOT NULL,
    tax_id VARCHAR(255), -- encrypted
    business_address JSONB NOT NULL,
    coordinates POINT, -- PostGIS for geographic queries
    roaster_id UUID REFERENCES roasters(id),
    status VARCHAR(50) DEFAULT 'pending',
    branding JSONB DEFAULT '{}',
    fundraising_settings JSONB DEFAULT '{}',
    feature_flags JSONB DEFAULT '{}', -- Cached from Stytch
    stripe_connect_account_id VARCHAR(255),
    total_raised DECIMAL(10,2) DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

**Organization Members Table Schema** [Source: architecture/database-schema.md#organization_members]:
```sql
CREATE TABLE organization_members (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    organization_id UUID REFERENCES organizations(id),
    user_id UUID REFERENCES users(id),
    stytch_membership_id VARCHAR(255),
    role VARCHAR(50) NOT NULL CHECK (role IN ('admin', 'campaign_manager', 'viewer')),
    permissions JSONB DEFAULT '[]',
    status VARCHAR(50) DEFAULT 'active',
    invited_at TIMESTAMP,
    joined_at TIMESTAMP,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(organization_id, user_id)
);
```

### Required Indexes
**Performance Indexes** [Source: architecture/database-schema.md#indexes]:
- `idx_users_stytch_id ON users(stytch_user_id)` - Fast Stytch user lookups
- `idx_organizations_stytch_id ON organizations(stytch_org_id)` - Organization ID lookups
- `idx_org_members_org_user ON organization_members(organization_id, user_id)` - Member queries
- `idx_customer_sessions_stytch ON customer_sessions(stytch_session_id)` - Session lookups
- `idx_organizations_coordinates ON organizations USING GIST(coordinates)` - Geographic queries
